## Introduction

The Brevio Harness runs agents that plan, build, test and release a product from a git repository.
It runs on one Linux server as a set of systemd user units, with one model provider, the Antigravity
CLI (`agy`), signed in on that server.

This tutorial prepares a Hetzner Cloud server with cloud-init, installs the harness, and checks the
install with its built-in doctor.

**Prerequisites**

- A Hetzner Cloud account and an SSH key added to it.
- Access to the Brevio Harness repository (the URL and a GitHub token or SSH key that can clone it).
- An Antigravity CLI (`agy`) subscription for the server.
- The GitHub credentials the harness uses for your product repository (see `docs/operations/env.md`).

## Step 1 - Create the server

In the Hetzner Cloud Console, create a server:

- Image: Ubuntu 24.04.
- Type: one that fits your product's build and tests, which run on this server.
- SSH key: yours.
- Cloud config: paste the contents of `deploy/templates/vm/cloud-init.yml` from the harness repository.

The cloud config installs Python 3.12 and git, creates the `brevio` user and lets its systemd user units
run after logout. It holds no secret: Hetzner stores user data with the server, so tokens go into
`env.sh` over SSH in step 3.

## Step 2 - Clone the harness

Log in and switch to the `brevio` user. The login message lists the remaining steps.

```bash
ssh root@<your_server_ip>
su - brevio
git clone <harness repository> ~/brevio-harness
cd ~/brevio-harness
```

## Step 3 - Fill in env.sh

```bash
cp env.sh.example env.sh
chmod 600 env.sh
nano env.sh
```

`env.sh` holds the secrets, tokens, hosts and paths of this server, and nothing else. Every key is
explained in `env.sh.example` and `docs/operations/env.md`.

## Step 4 - Install and sign in to agy

Install the Antigravity CLI into `~/.local/bin` and sign it in, as `docs/operations/agy.md` describes.
The harness uses no other model provider, so nothing that calls a model runs until `agy` works.

## Step 5 - Run the setup

```bash
./setup.sh
.venv/bin/pip install -e .
bash install_services.sh
```

`setup.sh` creates the workspace, clones the product repository, creates `.venv` with Python 3.12 and
installs the hash-pinned `requirements.lock`. `install_services.sh` writes and enables the systemd user
units.

## Step 6 - Check the install

```bash
bash scripts/fresh_vm_check.sh
```

The script runs `cli.py doctor` and prints a summary. It ends with `PASS` when no check fails. Each
failing line names the page in `docs/operations/` that says how to fix it.

## Conclusion

The server now runs the harness's scheduled units. `cli.py status` shows what they are doing, and
`cli.py doctor` checks the install again after any change.
