## Introduction

[n8n](https://n8n.io) is an open-source workflow automation tool. When you host it yourself, it can read your Google Search Console and Google Analytics 4 (GA4) data on a schedule, so you no longer have to export reports by hand.

In this tutorial you will:

* Run n8n with Docker Compose on a Hetzner Cloud server, behind Caddy for automatic HTTPS
* Create a Google service account that can read your data, without using your personal Google login
* Build an n8n workflow that pulls Search Console queries and finds pages that rank on positions 4 to 20 (often called "striking distance")
* Pull a GA4 landing page report in the same workflow

The service account only gets read access. If its key ever leaks, nobody can change your Search Console or GA4 settings with it.

**Prerequisites**

* A Hetzner Cloud server with Ubuntu 24.04 and at least 2 GB of RAM
* An [SSH key](https://community.hetzner.com/tutorials/howto-ssh-key) added to the server
* Docker and the Docker Compose plugin installed ([Installing Docker on Ubuntu/Debian](https://community.hetzner.com/tutorials/howto-docker-install))
* A domain or subdomain you can point at the server, such as `n8n.example.com`
* Owner access to a Google Search Console property and Administrator access to a GA4 property
* A Google account that can create a Google Cloud project

**Example terminology**

* Domain: `n8n.example.com`
* Server IPv4: `<10.0.0.1>`
* Website in Search Console: `https://www.example.com/` (URL-prefix property) or `sc-domain:example.com` (Domain property)
* GA4 property ID: `123456789`

## Step 1 - Point your domain at the server

Create a DNS record at your DNS provider:

| Type | Name | Value |
|------|------|-------|
| A | n8n | `<10.0.0.1>` |

If your server has IPv6 enabled, add an `AAAA` record with the server's IPv6 address as well.

Check that the record resolves before you continue. Caddy needs it to request the HTTPS certificate:

```bash
dig +short n8n.example.com
```

The command should print your server's IP address.

## Step 2 - Open the firewall ports

Caddy needs ports 80 and 443 to get a certificate and serve n8n. If you use a [Hetzner Cloud Firewall](https://docs.hetzner.com/cloud/firewalls/getting-started/creating-a-firewall), allow these inbound rules and apply the firewall to your server:

| Protocol | Port | Purpose |
|----------|------|---------|
| TCP | 22 | SSH |
| TCP | 80 | HTTP (certificate validation and redirect) |
| TCP | 443 | HTTPS |
| UDP | 443 | HTTP/3 (optional) |

Do not open port 5678. n8n will only be reachable through Caddy.

## Step 3 - Run n8n and Caddy with Docker Compose

Log in to your server and create a folder for the setup:

```bash
ssh root@<10.0.0.1>
mkdir -p /opt/n8n && cd /opt/n8n
```

### Step 3.1 - Create the Caddyfile

```bash
nano Caddyfile
```

Add the following, using your own domain:

```caddyfile
n8n.example.com {
    reverse_proxy n8n:5678
}
```

Caddy requests and renews a Let's Encrypt certificate for this domain on its own.

### Step 3.2 - Create the Compose file

```bash
nano compose.yaml
```

Add the following. Replace `n8n.example.com` with your domain and set `GENERIC_TIMEZONE` to your own time zone:

```yaml
services:
  n8n:
    image: docker.n8n.io/n8nio/n8n
    restart: unless-stopped
    environment:
      - N8N_HOST=n8n.example.com
      - N8N_PORT=5678
      - N8N_PROTOCOL=https
      - WEBHOOK_URL=https://n8n.example.com/
      - GENERIC_TIMEZONE=Europe/Berlin
      - TZ=Europe/Berlin
    volumes:
      - n8n_data:/home/node/.n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
      - "443:443/udp"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config

volumes:
  n8n_data:
  caddy_data:
  caddy_config:
```

The `n8n_data` volume keeps your workflows and the encrypted credentials when you update or restart the container.

### Step 3.3 - Start the containers

```bash
docker compose up -d
docker compose logs -f caddy
```

Wait until the Caddy log shows that the certificate was obtained, then press `Ctrl+C`. Open `https://n8n.example.com` in your browser and create the n8n owner account. Use a strong password: this account can see every credential you store in n8n.

## Step 4 - Create a Google service account

A service account is a Google identity for a program instead of a person. n8n will use it to call the Search Console API and the GA4 Data API.

### Step 4.1 - Create a project and enable the APIs

1. Open the [Google Cloud console](https://console.cloud.google.com/).
2. In the project dropdown at the top, select **New project**, give it a name such as `n8n-reporting` and select **Create**. Make sure the new project is selected.
3. Go to **APIs & Services** › **Library** and enable these two APIs:
   * **Google Search Console API**
   * **Google Analytics Data API**

### Step 4.2 - Create the service account and its key

1. Go to **APIs & Services** › **Credentials**.
2. Select **+ Create credentials** › **Service account**.
3. Enter a name such as `n8n-reader`, select **Create and continue**, skip the optional role, and select **Done**.
4. Open the new service account, go to the **Keys** tab and select **Add key** › **Create new key**.
5. Choose **JSON** and select **Create**. Your browser downloads a JSON file.

Copy the service account's email address. It looks like this:

```text
n8n-reader@n8n-reporting.iam.gserviceaccount.com
```

Keep the JSON file safe and delete it from your Downloads folder once Step 6 is done. It is a password for the service account.

## Step 5 - Give the service account read access

The service account has no access to your data yet. You add it as a user, the same way you would add a colleague.

### Step 5.1 - Search Console

1. Open [Search Console](https://search.google.com/search-console) and select your property.
2. Go to **Settings** › **Users and permissions** › **Add user**.
3. Paste the service account email and choose the **Restricted** permission.

Restricted users can read performance data, which is all this workflow needs.

### Step 5.2 - Google Analytics 4

1. Open [Google Analytics](https://analytics.google.com/) and go to **Admin**.
2. Under **Property**, open **Property access management**.
3. Select **+** › **Add users**, paste the service account email and choose the **Viewer** role. Turn off the email notification; nobody reads that inbox.
4. Under **Property** › **Property details**, copy the numeric **Property ID**, for example `123456789`.

## Step 6 - Add the credential to n8n

1. In n8n, open **Credentials** and select **Add credential**.
2. Search for **Google Service Account API** and select it.
3. Open the JSON file from Step 4.2:
   * Copy the `client_email` value into **Service Account Email**.
   * Copy the `private_key` value into **Private Key**, without the surrounding quotation marks.
4. Turn on **Set up for use in HTTP Request node**. A **Scope(s)** field appears.
5. Replace the scopes with these two, separated by a space:

   ```text
   https://www.googleapis.com/auth/webmasters.readonly https://www.googleapis.com/auth/analytics.readonly
   ```

6. Select **Save**.

Both scopes are read-only, so a workflow using this credential cannot change your Search Console or GA4 settings.

## Step 7 - Query Search Console from a workflow

Create a new workflow in n8n.

### Step 7.1 - Add a trigger

Add a **Schedule Trigger** node and set it to run once a week, for example every Monday at 07:00. While you build the workflow, you can run it with **Execute workflow**.

### Step 7.2 - Add the Search Console request

Add an **HTTP Request** node after the trigger and set:

* **Method:** `POST`
* **URL** (switch the field to **Expression**):

  ```text
  https://www.googleapis.com/webmasters/v3/sites/{{ encodeURIComponent('https://www.example.com/') }}/searchAnalytics/query
  ```

  Use the property exactly as Search Console shows it. For a Domain property, use `sc-domain:example.com` instead of the URL. `encodeURIComponent` takes care of the special characters in both forms.

* **Authentication:** `Predefined Credential Type`
* **Credential Type:** `Google Service Account API`, then select the credential from Step 6
* **Send Body:** on, **Body Content Type:** `JSON`, **Specify Body:** `Using JSON`
* **JSON** (switch the field to **Expression**):

  ```json
  {
    "startDate": "{{ $now.minus({ days: 31 }).toFormat('yyyy-MM-dd') }}",
    "endDate": "{{ $now.minus({ days: 3 }).toFormat('yyyy-MM-dd') }}",
    "dimensions": ["query", "page"],
    "rowLimit": 5000
  }
  ```

The end date is three days back because Search Console finalises its data with a delay of a few days. The API accepts up to 25,000 rows per request; use `startRow` to page through more.

Run the node. The output contains a `rows` array. Each row has `keys` (the query and the page), `clicks`, `impressions`, `ctr` and `position`.

### Step 7.3 - Find the striking-distance queries

Add a **Code** node after the HTTP Request node. Keep the mode at **Run Once for All Items**, choose **JavaScript** and paste:

```javascript
const rows = $input.first().json.rows || [];

return rows
  .filter(r => r.position >= 4 && r.position <= 20 && r.impressions >= 20)
  .sort((a, b) => b.impressions - a.impressions)
  .map(r => ({
    json: {
      query: r.keys[0],
      page: r.keys[1],
      clicks: r.clicks,
      impressions: r.impressions,
      ctr_percent: Math.round(r.ctr * 1000) / 10,
      position: Math.round(r.position * 10) / 10,
    },
  }));
```

The output is a list of queries where a page already ranks between positions 4 and 20 with at least 20 impressions. These pages usually move up fastest when you improve them. Adjust the thresholds to the size of your site.

## Step 8 - Add a GA4 landing page report

Add a second **HTTP Request** node, connected to the Schedule Trigger, and set:

* **Method:** `POST`
* **URL:**

  ```text
  https://analyticsdata.googleapis.com/v1beta/properties/123456789:runReport
  ```

  Replace `123456789` with your Property ID from Step 5.2.

* **Authentication:** `Predefined Credential Type`, **Credential Type:** `Google Service Account API`, same credential as before
* **Send Body:** on, **Body Content Type:** `JSON`, **Specify Body:** `Using JSON`
* **JSON:**

  ```json
  {
    "dateRanges": [{ "startDate": "28daysAgo", "endDate": "yesterday" }],
    "dimensions": [{ "name": "landingPage" }, { "name": "sessionDefaultChannelGroup" }],
    "metrics": [{ "name": "sessions" }, { "name": "keyEvents" }],
    "orderBys": [{ "metric": { "metricName": "sessions" }, "desc": true }],
    "limit": 100
  }
  ```

Run the node. Each entry in `rows` has `dimensionValues` (landing page and channel) and `metricValues` (sessions and key events) in the order you requested them. Filter the channel for `Organic Search` to see which landing pages bring search visitors that go on to complete a key event, such as a form submission.

## Step 9 - Send the results somewhere useful (optional)

You now have two lists in n8n. Common next nodes:

* **Google Sheets** › **Append or Update Row** to keep a weekly history
* **Telegram**, **Slack** or **Send Email** to send the top 10 striking-distance queries every Monday

When the workflow works, select **Publish** (or switch it to **Active**, depending on your n8n version) so the Schedule Trigger runs on its own.

## Step 10 - Troubleshooting

| Error | Cause and fix |
|-------|---------------|
| `403 User does not have sufficient permission for site` | The service account is not a user on that Search Console property, or the property in the URL does not match. Check Step 5.1 and use the exact property name (`https://www.example.com/` with the trailing slash, or `sc-domain:example.com`). |
| `403 ... API has not been used in project ... or it is disabled` | Enable the API in Step 4.1 for the same Google Cloud project that owns the service account. Wait a few minutes and run the node again. |
| `403 User does not have sufficient permissions for this property` (GA4) | Add the service account as a Viewer on the GA4 property (Step 5.2) and check the Property ID. |
| `401` or `invalid_grant` | The private key was pasted incorrectly. Copy `private_key` again from the JSON file, without the surrounding quotation marks. |
| Empty `rows` | The date range has no data yet, or the filters are too strict. Try a longer range. |

## Conclusion

Your n8n instance now runs on a Hetzner Cloud server behind HTTPS, reads Search Console and GA4 through a read-only service account, and produces a weekly list of the queries where your pages are closest to page one.

**Next steps:**

* Back up the `n8n_data` volume, for example with [restic to a Storage Box](https://community.hetzner.com/tutorials/storagebox-restic-docker-backup)
* Run Docker Compose as a service with [docker-compose-as-systemd-service](https://community.hetzner.com/tutorials/docker-compose-as-systemd-service)
* Read the [Search Console API reference](https://developers.google.com/webmaster-tools/v1/searchanalytics/query) and the [GA4 Data API reference](https://developers.google.com/analytics/devguides/reporting/data/v1/rest/v1beta/properties/runReport) for more dimensions, filters and metrics
